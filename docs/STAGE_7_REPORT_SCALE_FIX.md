# Отчёт об исправлении масштабирования экранных листов

## Дата
2026-01-29

## Проблема
Листы в окне "Пояснительная записка" рендерились в несколько раз крупнее панели (гигантские рамка и текст). Причина — scale считался без перевода мм→px.

## Диагностика

### Было (неправильно):
```typescript
const containerWidth = containerRef.current.offsetWidth; // пиксели
const sheetWidth = 210; // миллиметры (A4)
const newScale = containerWidth / sheetWidth; // ❌ Делим пиксели на миллиметры!
```

**Результат:**
- Если контейнер 800px, а лист 210мм
- Scale = 800 / 210 = 3.81 (381%)
- Лист увеличивается почти в 4 раза!

### Стало (правильно):
```typescript
const PX_PER_MM = 96 / 25.4; // ≈3.7795275591
const sheetWpx = sheetWidthMm * PX_PER_MM; // 210 * 3.78 = 794px
const containerWidthPx = containerRef.current.offsetWidth; // 800px
let k = containerWidthPx / sheetWpx; // 800 / 794 = 1.006
k = Math.min(k, 1); // Ограничиваем до 1.0 (100%)
```

**Результат:**
- Лист A4 = 794×1123 px
- Лист A3 landscape = 1587×1123 px
- Scale ограничен максимум 1.0 (100%)
- Лист не увеличивается больше оригинального размера

## Исправления в PageSheet.tsx

### 1. Добавлена константа конвертации
```typescript
const PX_PER_MM = 96 / 25.4; // ≈3.7795275591
```

### 2. Вычисление размеров в пикселях
```typescript
const sheetWpx = sheetWidthMm * PX_PER_MM;
const sheetHpx = sheetHeightMm * PX_PER_MM;

// A4 portrait: 210 * 3.78 = 794px × 297 * 3.78 = 1123px
// A3 landscape: 420 * 3.78 = 1587px × 297 * 3.78 = 1123px
```

### 3. Ограничение масштаба
```typescript
let k = containerWidthPx / sheetWpx;
k = Math.min(k, 1); // ОБЯЗАТЕЛЬНО не увеличивать больше 100%
```

### 4. Скрытие до первого замера
```typescript
const [scale, setScale] = useState(0.5); // Начальное значение 0.5
const [isReady, setIsReady] = useState(false); // Флаг готовности

// Скрываем лист до первого замера, чтобы не мигал "гигантом"
visibility: isReady ? 'visible' : 'hidden'
height: isReady ? `${sheetHpx * scale}px` : '0px'
```

### 5. Правильная структура DOM
```typescript
// Внешняя обёртка
<div style={{
  width: '100%',
  height: `${sheetHpx * scale}px`, // Высота = высота листа × масштаб
  overflow: 'hidden',
  visibility: isReady ? 'visible' : 'hidden'
}}>
  // Внутренний лист
  <div style={{
    width: `${sheetWpx}px`, // Ширина в пикселях
    height: `${sheetHpx}px`, // Высота в пикселях
    transform: `scale(${scale})`, // Масштабирование
    transformOrigin: 'top left'
  }}>
    {/* Рамка, контент, штамп */}
  </div>
</div>
```

### 6. Толщина рамки
```typescript
border: '0.4mm solid #000' // Было 0.5mm, стало 0.4mm
```

**Причина:** При малых k (0.5-0.7) рамка 0.5mm превращалась в "жирную полосу". 0.4mm после scale визуально даёт ~1-2 px.

## Технические детали

### Формула масштабирования

```
PX_PER_MM = 96 / 25.4 ≈ 3.7795275591

sheetWpx = sheetWidthMm × PX_PER_MM
sheetHpx = sheetHeightMm × PX_PER_MM

k = containerWidthPx / sheetWpx
k = Math.min(k, 1) // Ограничение до 100%

wrapperHeight = sheetHpx × k
```

### Примеры расчётов

**A4 portrait (210×297 мм):**
- sheetWpx = 210 × 3.78 = 794 px
- sheetHpx = 297 × 3.78 = 1123 px
- При containerWidth = 800px: k = 800/794 = 1.006 → 1.0 (100%)
- При containerWidth = 600px: k = 600/794 = 0.756 (75.6%)
- При containerWidth = 400px: k = 400/794 = 0.504 (50.4%)

**A3 landscape (420×297 мм):**
- sheetWpx = 420 × 3.78 = 1587 px
- sheetHpx = 297 × 3.78 = 1123 px
- При containerWidth = 1600px: k = 1600/1587 = 1.008 → 1.0 (100%)
- При containerWidth = 800px: k = 800/1587 = 0.504 (50.4%)
- При containerWidth = 600px: k = 600/1587 = 0.378 (37.8%)

### Почему visibility: hidden до первого замера?

**Проблема:**
- При первом рендере containerRef.current.offsetWidth = 0
- Scale = 0.5 (начальное значение)
- Лист рендерится с scale 0.5, но без ограничения по высоте
- Визуально выглядит как "гигант" на долю секунды

**Решение:**
- Установить isReady = false до первого замера
- Скрывать лист через visibility: hidden
- После первого замера установить isReady = true
- Показать лист с правильным scale

**Результат:**
- Нет мигания "гигантом"
- Плавное появление листа
- Корректное масштабирование с первого кадра

### Почему Math.min(k, 1)?

**Проблема:**
- Если containerWidth > sheetWpx, то k > 1
- Например: containerWidth = 1600px, sheetWpx = 794px
- k = 1600/794 = 2.01 (201%)
- Лист увеличивается в 2 раза!

**Решение:**
- Ограничить k максимум 1.0 (100%)
- Лист никогда не будет больше оригинального размера
- При большом контейнере лист центрируется (или прижимается к левому краю)

**Результат:**
- Лист A4 никогда не будет больше 794×1123 px
- Лист A3 landscape никогда не будет больше 1587×1123 px
- Нет "гигантских" листов при широких панелях
