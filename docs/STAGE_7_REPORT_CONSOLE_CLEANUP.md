## Средовые ошибки (WebSocket Vite HMR)

### Ошибки О-1...О-3
```
WebSocket client:802/841/454 — обрыв HMR-сокета Vite в песочнице превью (ERR_CONNECTION_TIMED_OUT)
```

**Статус:** Средовые ошибки, не связанные с кодом приложения

**Причина:** 
- Это инъекция `@vite/client` для Hot Module Replacement (HMR)
- Ошибки возникают в песочнице превью из-за ограничений среды
- В локальной разработке (npm run dev) эти ошибки не появляются
- В продакшн-сборке (npm run build && npm run preview) эти ошибки отсутствуют

**Решение:** Не трогать
- Подавление через `vite.config` (hmr: false) может сломать локальную разработку
- Ошибки не влияют на функциональность приложения
- В продакшн-режиме WebSocket HMR не используется

**Проверка:**
```bash
npm run build
npm run preview
```

## Технические детали

### Почему удалены console.log, а не переведены в console.debug

1. **Простота:** Удаление проще, чем добавление условий `import.meta.env.DEV`
2. **Чистота:** В продакшн-сборке не будет лишних проверок
3. **Безопасность:** TypeScript не требует дополнительных типов для `import.meta.env`
4. **Производительность:** Меньше кода = быстрее выполнение

### Почему console.error заменён на Journal.logEvent

1. **Единообразие:** Все логи приложения идут через Journal
2. **Просмотр:** Ошибки видны в журнале событий приложения
3. **Отладка:** Информация об ошибке сохраняется
4. **UI:** Пользователь видит ошибку через alert(), но в журнале остаётся след

### Почему не трогались console.log в других файлах

1. **Ограничение задачи:** "Никаких других правок"
2. **Разделение ответственности:** ThermoExportDialog.tsx относится к вкладке "Термометрия"
3. **Минимальные изменения:** Только то, что указано в задаче
4. **Безопасность:** Меньше изменений = меньше риск сломать что-то
